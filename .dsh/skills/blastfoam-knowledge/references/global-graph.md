# 全局来源定位图

本文件描述旧全局来源卡片协议。新版手册的章节与完整证据构建、第 5 章语义提取使用[章节与原文证据图](manual-graph.md)。旧 `build_global.py` 虽已读取 Markdown，仍按字符切分，不能代替新的手册构建入口。

现行重建仅使用精确模型名 `deepseek-flash`。旧模型缓存不复用到新计划；模型标识属于缓存键和发布校验的一部分。教程按案例分组，再切分文件块。几何、网格和数值资源保留原件与结构索引，不把它们作为自然语言抽取材料。

模型生成实体、关系、条件及引用。确定性校验要求引用能在给定原文中唯一定位，只忽略空白差异；无法定位的候选进入拒绝记录。实体按种类、命名空间、原始名称区分，不模糊合并相似模型名。案例归属来自文件清单。引用正确只证明出处可定位，不证明物理解释正确；公式、复杂表格和图片仍须查看原页。

查询先匹配实体名称，再沿关系查找来源卡片，按名称精确匹配数、命中词数和稳定来源顺序返回。没有文档 BM25、训练权重或基于评测题目的规则。`query_global.py` 将卡片及其引用附近原文打包，完整条目超出预算即停止；单段原文最多 1200 字符。预算不包含调用方生成实体查询时消耗的提示词，因此评测另记规划成本。

## 教程增删改

1. 将变化同步到 `corpus/tutorials/`，包括删除旧文件；保留必要的原始资源。
2. 运行 `python scripts/build.py` 和 `python scripts/validate.py`，更新案例清单及结构关系。
3. 运行下面的全局构建命令。报告目录放在 skill 外；密钥文件不复制进 skill。

```bash
python scripts/build_global.py --model deepseek-flash --run-dir /path/to/external-report --key-file /path/to/api-key --workers 4
```

缓存键包含抽取单元的来源内容、模型及提示词。未变化单元复用缓存，变化单元重新抽取；删除的单元不进入新图，即使旧缓存仍存在。切分边界变化也可能影响同一案例后续单元。

全部单元处理完成、来源哈希一致后才发布 `semantic/global/current.json`。失败可原命令续跑，保留成功单元。`releases/<snapshot>/manifest.json` 分别记录处理覆盖、接受/拒绝数量、资源文件及未完成的语义/视觉复核；不能把“全部单元已处理”写成“全部知识已验证”。

评测问题、私有标注和结果不进入 skill 语料。全局评测分别比较文本、结构图、同一查询规划下的文本、语义图，记录多个字符预算下的证据定位、上下文开销和规划成本。它不等于真实 coding agent 的端到端正确率。
