# 需求定位入口

`scripts/locate.py --query "原需求" --translation "可选忠实英文表达" --domain-index <外部领域图.json> --budget 3000` 不要求已暴露节点ID。预算约束整个JSON的Unicode字符数。`--case`精确限定案例，`--index`复用配置证据图，`--audit`写外部审计。

## 构建与覆盖

```bash
python scripts/domain_graph.py --foundation <基础图.json> --semantic <语义图.json> --review <审核.json> --output <外部领域图.json>
```

复用manual_graph.py全书章节、原文及显式引用。只接受审核记录中明确accept的语义事实；核对基础图/语义快照、原文哈希、引句和范围。当前可复用87条事实只覆盖第5、7、9、19章，不是全书语义覆盖。既有作者审核不等于独立专家复核。

未传`--domain-index`时只自动构建全书结构关系，没有已审核语义事实。`semantic_facts_available`显示加载事实数；需要领域条件时必须传入已编译的审核图。编译图固定构建器、基础来源和审核摘要，变更后需重建。

## 定位与结果

显式案例路径优先于同名匹配；同名案例跨求解器时保留候选。`matched_cases`显示最多三个名字，全部匹配在审计中，不自动拼接不同案例。初始位置考虑原文、真实章节标题、来源路径和明确提及的类型声明，最多三个。调用智能体可以补充忠实英文表达，但不是通用自然语言理解保证。

图导航最多两跳、三条关系，可以反向发现引用来源；`traversal`只表示发现方向，不能反转逻辑含义。同案例脚本仅在需求涉及流程、网格或初始化时参与。显式引用可在已引用章节内按实际出现的小节名定位定义，不全书猜测同名实体。

事实候选包含命中章节，以及主体/客体与查询词重合的祖先章节事实；不沿同级章节传播。限制、必要条件和输入在候选排序中优先。`scope_note`提醒调用者逐项核对主体和条件，父章节事实不自动适用于所有子模型。

`facts`优先于附加邻居，占同一预算，包含主体、关系、客体、条件和逐字来源引句。已返回引句无需再读取。多依据事实超预算时整体略过，不拆成失去条件的断言。`locations.preview`是最多320字符的真实前缀，可能截在行内；`preview_complete`说明是否读完整个范围。定位范围不是已读范围，长段需要source补查。`relations`只连接实际返回位置。原文含有的版本差异应保留，命中不证明物理适用，无命中不证明功能不存在。

## 对照

`--text-only`保留根位置匹配、范围与预算，关闭关系扩展及语义事实输出。不带语义输入构建的领域图可作为“仅结构”组，带审核事实则是“结构＋语义”组。旧locator_evaluation/run01冻结代码和结果保持不变。新图的覆盖和真实累计成本需另行检查，不能以关系数量增加宣称收益。
