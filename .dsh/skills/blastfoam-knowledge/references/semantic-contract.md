# 后续语义事实与修改依赖扩展约定

这是待实现阶段的设计约定。当前完成的是结构图谱和有界证据排序，尚未完成全书语义抽取或完整修改影响推理。

## 全书语义抽取

按原书小节建立覆盖清单，追踪正文、表格、公式、配置示例、图注的处理状态。每项只能标记未处理、已抽取待审核、已审核、无法可靠转录或不适用；出现图谱节点不等于该小节的知识已全部抽取。跨页表格与公式必须绑定全部相关区域，不能只保留标题页。

每条事实至少包含：稳定逻辑 ID、主体、关系、客体、适用条件、来源版本、证据定位、抽取方法、审核状态和冲突记录。主体区分通用模型、参数定义、案例配置实例和当前任务的推断。参数定义包含单位/量纲及其原文依据；参数值属于案例实例，不因多个教程取值相同而升级为默认值或推荐值。

证据定位保留原始文件哈希、PDF 页、区域 ID/坐标或文件行范围。数学内容保留原图；无法确认上下标、符号、单位时不得发布为可自动计算的事实。抽取器可以由 LLM 辅助，但 JSON 可解析、引用可定位不等于语义正确。先执行结构/类型/单位检查，再做逐条或分层抽样的领域审核，高影响参数约束须单独核对。

事实的来源状态与真实性状态分开：原文明示、解析器确认、模型推断描述“怎样得到”；未核对、交叉核对、有冲突描述“验证到什么程度”。不要给原文明示的陈述自动赋予物理真实性 1.0。证据冲突不能通过数量投票消除。

## 修改依赖推理

候选关系包括读取文件、生成产物、引用边界名、选择模型、约束参数、执行前置条件、需要重建产物。必须保留条件：求解器、模型选择、几何维度、串并行阶段和工具参数等。`NEXT_IN_SCRIPT` 不能自动转换为无条件 `REQUIRES`；参数同现不能自动转换为联动修改。

推理输入是明确的变更集合与目标案例快照，输出区分：必须调整、有条件调整、建议检查、证据不足。每项附带触发的事实、条件判断和解释路径；条件未知时保留未知，不按真处理。输出检查事项不等于自动执行命令或自动编辑文件。

“完整”必须相对于公开的受支持变更集合与解析边界定义，例如几何/网格、初始化区域、模型选择、边界命名、监测配置。外部脚本、动态表达式、运行时生成的配置尚不能解析时，报告覆盖缺口，不能宣称任意修改的依赖完整。

## 增量维护与验收

语义抽取结果按语料哈希、抽取 schema、模型/提示版本和审核修订固定；教程变化时只失效相关事实与反向依赖，稳定手册事实可复用。案例删除撤销其支持来源，共享定义与其他证据保留。更换解析器或提示需要明确失效策略，禁止混用不同语义版本而不记录。

进入模型抽取阶段前，应拆分抽取版本与检索版本：只修改排序器不能触发全书模型重抽。当前结构抽取器与排序代码仍共用工具哈希，本轮排序升级因而重建了结构缓存；这不是未来昂贵语义抽取的目标失效策略。

验收使用独立任务族和反事实成对案例：仅改变一个模型、边界名或步骤条件，检查受影响集合是否相应变化；检查未触发条件时不产生错误依赖；改变文件顺序、节点 ID、案例名称不应改变物理结论。实际执行验证另行安排，静态图谱不能代替 OpenFOAM 运行和数值检查。

全书覆盖率、语义事实准确性、依赖覆盖率、错误依赖率和检索/回答效果分别报告。禁止根据测试题回填事实或专门添加通往标准答案的边；补充事实必须由语料独立支持。已用于调参的题目不能再次充当盲测。
