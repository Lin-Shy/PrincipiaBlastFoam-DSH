# blastFoam 知识检索

目标是用少量来源回答“修改什么、怎么修改、哪些关联设置需要核对”。关系连同条件和出处使用；结构邻接不保证物理适用，教程示例不是通用默认值。

## 选择入口

已知教程案例、但需要完整字典路径或关联修改时，优先调用 `mcp__principia_retrieval__locate_case_edits`。传入用户原始需求 `query` 和案例标识 `tutorial_case`（格式为 `<求解器>/<案例>`，不是实际目录路径）；可在 `translation` 中补充忠实英文表达，默认 `budget=5000`。这类任务通常无需先获取状态、列出全部文件或逐个猜测变量。

- 已有准确来源位置时直接读取，不为使用图谱追加定位调用。
- 案例尚不明确时，先用 `get_case_by_intent` 或案例搜索确定候选；相关性不是物理适用性判定。
- 定位偏离需求、无命中或依据不足时，围绕具体缺口补查手册、变量或文本；避免重新读取已经完整返回的证据。

`locations` 给出文件、字典作用域、行号和原文；`complete=false` 表示片段不完整。`conditions` 的 `requirements` 只在其前提成立时提供修改依据；示例差异本身不构成必改理由。

使用 `mcp__principia_retrieval__read_knowledge_source` 按返回的 `path/start/end` 补读来源。该工具读取的是技能内的固定语料；要判断实际副本现状，使用副本文件或下面的状态检查。不要默认为外部教程与固定语料完全一致。

## 结束取证并推进任务

当请求的修改已对应到完整字典路径、当前值、拟修改值及支持其语义的来源，且没有影响方案的未解决矛盾时，直接完成修改说明，或进入用户已要求的编辑与验证。无需为同一结论继续寻找第二个教程示例，也无需遍历所有可能的关联问题。

继续检索前先明确尚缺的事实，以及它会改变哪项修改；若只是重复确认已有结论，使用已有证据。运行后的步长、误差和物理效果若未验证，应明确保留不确定性，不以推测补齐，也不因这些未请求的预测无限扩展只读任务。实际编辑或运行暴露的新错误仍应取证处理。

## 检查实际副本

编辑后核对依赖，或用户要求检查已有副本时，可调用 `mcp__principia_retrieval__check_case_dependencies(case_path, tutorial_case)`。实际目录必须位于配置的案例根目录内。

`inactive_for_current_inputs` 表示这条规则不支持在当前输入下声称相关配置是必需的；若建议仍依赖该规则，应修正建议或补充其他依据。此状态不要求自动删除已有文件。`not_evaluated`/unknown 不能当作适用或通过；修改后的新状态也不能由旧判断代替。当前只覆盖有限的审核规则，不能替代配置解析、运行验证或物理判断。

## MCP 不可用及维护

可在技能目录使用 Python 3.11+ 的本地脚本。已知案例可执行 `scripts/condition_graph.py --condition-index references/conditional_requirements.json --original "<原始需求>" --case "<求解器>/<案例>" --budget 5000`。未知案例、批量检索、手册图维护及其他 CLI 入口按需阅读 [CLI 查询与维护](references/cli-workflows.md)，不要在普通取证任务中重建索引。

回答引用实际读到的来源，区分当前配置、条件依赖、示例和未确定事项。只读任务不扩展为编辑或执行。评价看回答及构建质量和累计成本，不能用单次字符数或调用了图谱代替效果证据。
