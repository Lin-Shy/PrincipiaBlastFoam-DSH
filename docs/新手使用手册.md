# DSH 新手使用手册

更新：2026-10-13。适用于当前 Windows 本地 DSH + Linux 非 root SSH 环境。

**先记住：打开 DSH，只是打开操作界面，不会自动开始整章实验。** 你需要在界面中选模型、选工作区，再提交任务。

| 你要做什么 | 目前能不能做 |
| --- | --- |
| 打开第3章的多角色环境 | 可以 |
| 打开第4章的独立单 agent 环境 | 可以 |
| 通过 yan_yun_agent 读写 Linux 文件、运行 Bash、搜索和检查 blastFoam | 已验证 |
| 检查第3章题集和批量运行命令（dry-run） | 可以，不调用模型、不运行仿真 |
| 一键运行第3章 Windows→SSH 完整批量实验并自动评分 | 尚未接通，不能直接照搬旧批量命令 |
| 一键运行第4章自动递归自改进（RSI）实验 | 尚未实现运行器，目前只有设计 |

两章插件和模型怎么设置，见[第3章与第4章插件配置指南](插件配置指南.md)。当前第3章使用多角色 bundle，第4章使用独立 SSH 配置并自动关闭子 agent。

## 1. 每天怎么打开 DSH

### 第一步：打开本地代理

打开你平时使用的代理软件，保持 **7897 端口**可用。Linux 下载组件需要它，启动脚本会自动建立或复用 SSH 代理转发。

### 第二步：在正确的文件夹打开 PowerShell

用 Windows 资源管理器打开 **graduation-projects 总目录**。工程源码在 PrincipiaBlastFoam-DSH，论文等材料在 graduation-thesis-materials。

点击资源管理器上方的地址栏，输入 powershell，按回车。下面所有命令都在这个窗口中执行。只复制代码框中的命令，不要复制终端前面的 PS 提示符。

### 第三步：选择要打开哪一章

**打开第3章：**

~~~powershell
./PrincipiaBlastFoam-DSH/deployment/windows/Start-Principia.ps1 -Chapter 3 -Ssh
~~~

**打开第4章：**

~~~powershell
./PrincipiaBlastFoam-DSH/deployment/windows/Start-Principia.ps1 -Chapter 4 -Ssh
~~~

第一次先只开一章。切换章节时，先按 Ctrl+C 停止当前界面，再运行另一条命令。

启动后终端会显示 dsh web: 和一个网址。浏览器通常会自动打开；如果没有，就复制终端输出的**完整网址**到浏览器，包括 token 参数。不要把这个登录网址分享给别人。

终端一直占着、不再出现新的输入提示符，是正常现象：DSH 正在运行。不要为了“让命令结束”而关闭窗口。

### 第四步：选模型，再选工作区

如果还没有可用模型，在 DSH 的设置中找到模型/服务商配置，填入服务商提供的地址、模型名称和 API Key，再在会话里选择该模型。第3、4章的配置相互隔离，第4章可能需要单独配置。密钥只填本机配置，不写进论文、手册或聊天截图。

在工作区列表中选择：

| 当前章节 | 应选的远程工作区 |
| --- | --- |
| 第3章 | yan_yun_agent > chapter3 |
| 第4章 | yan_yun_agent > chapter4 |

如果没看到，进入 Settings → Remote SSH，确认 Host 为 yan_yun_agent；使用 Test 检查连接，再从远程工作区入口选择对应目录。

选择远程工作区后新建会话。如果会话仍选择 Local，文件和命令就仍在 Windows 执行。SSH 已连接，也不代表这个会话已经选中 Linux 工作区。

当前两个远程目录已分别建立在 agent 用户的 home 下。实际路径由本机 .local/windows.ps1 配置；不需要手动复制 Windows 项目到 Linux。第4章不要选择第3章目录或加载第3章的多角色配置。

### 第五步：第一次先做只读检查

在聊天输入框粘贴：

~~~text
请先做只读环境检查：用 Bash 显示当前用户、当前目录，检查 blastFoam 和 rg 是否可用，并运行 blastFoam -help。不要创建算例、修改文件或启动真实求解。请展示命令和实际输出。
~~~

预期：用户为 agent，目录属于所选章节的远程工作区，blastFoam 能显示帮助，rg 能使用。看到这些实际输出，才说明会话正在使用 Linux 环境。

## 2. 第3章怎么开始

### A. 先在界面中练习任务

用第3章启动命令，选中 chapter3 远程工作区，新建会话。第3章配置包含协调与五类专家能力；是否实际调用这些角色，要以会话里的工具记录为准。

第一次可以先输入：

~~~text
我准备做一次最小 blastFoam 试运行。请检查当前远程工作区和可读取的教程，提出一个适合短时验证的算例方案、需要修改的项目和完成检查项。只给方案和实际检查依据，暂不启动求解。后续只允许在当前工作区的新副本中操作，使用 agent 身份。
~~~

这是**手动试点准备**，不会自动生成一整章的统计结果。真实求解后还需要检查算例配置、退出状态、时间目录、必要场文件和任务要求的输出，不能只看聊天里说“成功”。

当前 SSH 基础工具已打通，但第3章原有的本地领域 MCP、完整多角色产物流程和正式评分还没有自动迁移到远端。若出现 Windows 路径或本地 solver 报错，先记录问题；不要改成 root，也不要把一次失败的界面试运行当作正式结果。

### B. 先检查批量实验命令，不花模型费用

这一步叫 dry-run，也就是“只检查运行计划”。可以在另一个 PowerShell 窗口执行，仍从 graduation-projects 总目录开始。

先建立本次检查结果目录：

~~~powershell
$resultPath = Join-Path $env:TEMP ('principia-chapter3-check-'+(Get-Date -Format 'yyyyMMdd-HHmmss'))
~~~

再复制下面**整条命令**：

~~~powershell
./PrincipiaBlastFoam-DSH/.venv/Scripts/python.exe ./PrincipiaBlastFoam-DSH/experiments/end2end/run_agent_benchmark.py --cases-file ./graduation-experiment-results/chapter3_end_to_end_evaluation/data/e2e_agent_benchmark_cases.json --output-root $resultPath --dsh-home ../dsh-home/chapter3 --limit 1 --disable-execution --dry-run
~~~

成功后，终端会输出 benchmark_report.json 的路径。打开结果文件夹：

~~~powershell
Invoke-Item $resultPath
~~~

里面有 run_时间戳 文件夹，以及报告和日志目录。报告中的 dry_run 为 true、execution_enabled 为 false 是预期结果；它没有调用模型，也没有运行求解器。报告存在不代表题目已经完成。

**目前不要删除 --dry-run 就直接开跑。** 现有适配器默认使用本地 headless 环境，其路径、远端执行和评分尚未与当前 web-ssh 链路完成联调。正式批量实验还需要专用 SSH 适配、一个真实短算例验收、固定模型和题集、独立输出目录及评分核验。

### C. 结果应该放哪里

手动远程任务文件在所选 Linux 工作区及你创建的任务子目录中；不会自动出现在 Windows 正式归档里。上面的 dry-run 结果临时保存在 Windows TEMP 目录，适合检查，不能当作长期实验归档。

正式第3章活动应在 graduation-experiment-results/chapter3_end_to_end_evaluation/ 下新建独立目录，保存协议、运行、日志和评分；保留旧活动，不覆盖历史结果。具体操作见[第3章适配器说明](../experiments/end2end/README.md)。

## 3. 第4章怎么开始

用第4章启动命令，选中 chapter4 远程工作区，新建会话，并先运行上面的只读检查。

这个入口已经隔离第3章 bundle，并关闭 subagent、fork 和 workflow 工具。第4章默认只使用一个 agent。

**目前能启动的是第4章的单 agent 开发环境，还不能启动完整的自动 RSI 实验。** 发一条任务给它，不会自动产生“执行→自诊断→提出改进→验证→接受/回退→继续下一轮”的实验闭环。

后续需要实现 RSI 运行器，固定初始版本、模型、训练/开发/测试任务和评分器，才能运行冻结基线、一次性改进、多轮递归改进三个对照。当前没有可复制的一键正式运行命令，也没有 DSH RSI 收益结果。

第4章的任务、技能和改进版本独立维护，不拿第3章的角色系统或轨迹当作默认来源。详细实施状态见[第4章说明](../experiments/self_evolution/README.md)和[实验计划](../experiments/self_evolution/PLAN.md)。

## 4. 怎么停止、重开和同时开两章

关闭网页不会停止 DSH。先确认任务已经结束或已取消，再回到启动它的 PowerShell 窗口按 Ctrl+C；重开时再执行同一条启动命令。

如果已经启动真实求解，不要假定关闭网页或停止 Web 就会停止远端求解，先确认任务状态。后台代理转发可以跨章节复用。

如果确实要同时开两章，在两个 PowerShell 窗口中分别启动。第3章用普通命令；第4章改用不同端口：

~~~powershell
./PrincipiaBlastFoam-DSH/deployment/windows/Start-Principia.ps1 -Chapter 4 -Ssh -TaskArguments @('--port','3004')
~~~

分别打开各自终端输出的网址，避免看错章节。

## 5. 常见问题

| 现象 | 怎么处理 |
| --- | --- |
| 找不到 Start-Principia.ps1 | 回到 graduation-projects 总目录，再复制命令；不要在子目录原样运行 |
| 浏览器返回 401 / 未授权 | 使用本次启动终端输出的完整网址，不要只输入 localhost，也不要用上次的 token |
| 提示 7897 代理不可用 | 确认本地代理软件正在运行，监听端口为 7897，再重试 |
| SSH 提示 Permission denied | 先用下面的 SSH 检查命令；目标应为 yan_yun_agent |
| 聊天提示没有模型或 API Key | 检查当前章节的模型配置及会话模型选择；能打开页面不等于模型已配置 |
| 端口已占用 | 停止之前的 DSH，或使用上面的另一端口命令 |
| 命令仍在 Windows 执行 | 检查会话工作区是否为 yan_yun_agent > chapter3/chapter4 |
| 看不到第4章多轮实验按钮 | 当前没有 RSI 自动运行器，不能靠界面按钮启动正式自改进实验 |

单独检查免密码登录：

~~~powershell
ssh -o BatchMode=yes -o ClearAllForwardings=yes yan_yun_agent "id -un"
~~~

预期输出 agent。此命令不运行仿真。

如果 Windows 提示禁止执行脚本，可以用下面的命令只对本次进程放行，不修改全局策略：

~~~powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./PrincipiaBlastFoam-DSH/deployment/windows/Start-Principia.ps1 -Chapter 3 -Ssh
~~~
