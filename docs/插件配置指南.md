# 第3章与第4章插件配置指南

更新：2026-10-13。配合[新手使用手册](新手使用手册.md)阅读。以下操作从 graduation-projects 总目录打开 PowerShell 后执行。

## 1. 先认清两章分别加载什么

当前已经安装好这些组件，日常使用不用重新安装。

| 组件 | 第3章 | 第4章 | 作用 |
| --- | --- | --- | --- |
| @deepseek-ai/dsh-base | 加载 | 加载 | DSH 基础能力 |
| @deepseek-ai/dsh-web-app | 加载 | 加载 | 浏览器操作界面 |
| dsh-remote-ssh | 加载 | 加载 | 通过 yan_yun_agent 使用 Linux 文件、Bash 和搜索 |
| principia-blastfoam-dsh-bundle | 加载 | 不加载 | 第3章工作策略、检索 MCP、五类专家工具 |
| single-agent.patch.example.yml | 不使用 | 自动使用 | 关闭子 agent 和 workflow；这是配置补丁，不是另一个插件 |

两章使用不同的 DSH_HOME，且 SSH 模式都用各自的 web-ssh profile。模型、密钥、会话与用户设置分别保存；在第3章保存的设置不会自动复制给第4章。

插件提供功能；Skill 提供模型可阅读的操作方法；MCP 提供外部工具。它们不是同一个安装入口。本项目 .dsh/skills 中的技能也不能理解为已安装的 npm 插件。远端会话能否发现和加载某个 Skill，应以实际工具记录为准。

## 2. 两章共用的设置：模型与 SSH

先打开目标章节：

~~~powershell
# 第3章
./PrincipiaBlastFoam-DSH/deployment/windows/Start-Principia.ps1 -Chapter 3 -Ssh
~~~

~~~powershell
# 第4章
./PrincipiaBlastFoam-DSH/deployment/windows/Start-Principia.ps1 -Chapter 4 -Ssh
~~~

按启动终端给出的完整网址进入界面，然后做以下设置：

1. 在设置中的模型/服务商配置填入服务商地址、准确模型名称和 API Key；回到会话选择模型。两章分别配置。
2. 打开 Settings → Remote SSH，找到 yan_yun_agent，点击“测试”。既有公钥登录已经配置，不需要再添加 root 主机。
3. 在工作区列表选择 yan_yun_agent 下对应的 chapter3 或 chapter4 目录，再新建会话。选择 Local 的会话仍在 Windows 执行。
4. 如需额外任务目录，在 Remote SSH 中选择 yan_yun_agent，使用“浏览远端…”选择 agent 可写目录，然后“添加工作区”。不要把第4章任务放进第3章工作目录。

启动脚本已经从本机配置注入默认主机与默认目录。更改这几个默认值时，编辑本机文件：

~~~powershell
notepad ./PrincipiaBlastFoam-DSH/.local/windows.ps1
~~~

| 本机变量 | 设置什么 |
| --- | --- |
| PRINCIPIA_SSH_HOST | SSH Host 别名，当前是 yan_yun_agent |
| PRINCIPIA_SSH_CHAPTER3_WORKSPACE | 第3章默认 Linux 工作目录 |
| PRINCIPIA_SSH_CHAPTER4_WORKSPACE | 第4章默认 Linux 工作目录 |
| DSH_REMOTE_SSH_CODE | 远端已安装的 code-with-env 启动包装器路径 |
| PRINCIPIA_SSH_PROXY_PORT | Windows 本地代理端口，当前为 7897 |

保持现有包装器路径，它负责把 OpenFOAM、blastFoam 和 rg 的环境传给远程工具。Linux 路径填 Linux 的绝对路径；不要填 Windows 盘符。修改后停止 DSH，再重新运行章节启动命令。本机文件不提交 Git；不要把密钥写入共享配置模板。

## 3. 第3章：怎样配置多角色和检索插件

### 在网页里可以改什么

设置 → 插件 → 插件配置，用于修改已经加载、且提供配置卡片的宿主插件。修改后要点“保存”；“重置”恢复部署默认值。“插件列表”用于查看加载情况，不是安装商店。

如要允许子 agent 选择其他模型，可在 subagent-model-selection 卡片中开启并勾选已配置的准确模型路由，再保存；开启时至少选择一条有效路由。这个列表表示允许选择哪些模型，不能把它当作“五位专家分别固定使用哪个模型”的配置。没有此需求时保持默认值即可。

### 专家职责和工具权限在哪里改

第3章五类专家由应用 bundle 注册：

| 专家 | 配置 id | 模型可调用工具 |
| --- | --- | --- |
| 物理分析 | principia-physics-analyst | blastfoam_physics_analyst |
| 算例设置 | principia-case-setup | blastfoam_case_setup |
| 求解执行 | principia-execution-specialist | blastfoam_execution_specialist |
| 后处理 | principia-postprocessor | blastfoam_postprocessor |
| 质量审查 | principia-reviewer | blastfoam_quality_reviewer |

这些配置的维护入口是 [bundle 配置](../packages/principia-dsh-bundle/cordis.patch.yml)。其中 persona 是职责提示，toolFilter.allow 是工具白名单，maxDepth 是子 agent 深度限制。共用工作策略位于 [策略插件源码](../packages/principia-dsh-bundle/src/index.ts)。它们没有独立网页配置卡片；卡片未出现不代表没有加载。

初学者先使用现有配置。确实要调整某专家时，修改对应 id 的配置，并保留原有职责与只读/可写边界；审查专家继续只读。修改源码后需要重新构建 bundle；修改配置后重新启动 DSH，并核对生成配置。不要修改 deepseek-harness 上游来实现应用角色变化。

只对本机临时覆盖时，可编辑第3章 profile 的 cordis.patch.yml：

~~~powershell
notepad ../dsh-home/chapter3/profiles/web-ssh/cordis.patch.yml
~~~

配置补丁按 id 定位，config 会整体替换，不能只写一个 persona 就假定其他字段全部保留。应复制该角色完整 config 后修改。应用长期配置仍维护在项目 bundle；本机临时补丁不提交 Git。

### 检索 MCP 和 SSH 是两个独立入口

检索配置在同一个 bundle 文件的 principia-retrieval-mcp 下，使用 Windows 项目的 Python 启动领域服务。机器路径通过 .local/windows.ps1 中的 PRINCIPIA_PYTHON、BLASTFOAM_TUTORIALS 等变量提供；具体变量见[部署说明](../deployment/dsh/README.md)。

**安装 Remote SSH 不会自动把这些 MCP 工具搬到 Linux。** 例如求解专家当前白名单主要是 MCP 求解工具，没有通用 Bash；它不会仅因为已连接 SSH 就自动通过 Bash 运行 blastFoam。当前 Windows 启动脚本关闭本地领域服务的求解执行。正式远端多角色实验仍需单独适配和验收，不能只打开 ENABLE_EXECUTION 就认为接通。

## 4. 第4章：怎样设置单 agent 的插件

第4章使用独立模型配置、Remote SSH 和工作目录。按第2节设置即可，先用默认插件，不加载第3章 bundle。

[single-agent 补丁](../deployment/dsh/single-agent.patch.example.yml)由启动脚本自动加载，关闭 subagent、fork、子 agent 控制/列表、workflow 与 worker thread。无需在网页逐一寻找这些开关。即使基础组件使界面出现 subagent 相关卡片，也不表示第4章启用了多 agent；不要为了沿用第3章操作而打开这些功能。

后续需要检索、任务技能或 RSI 改进能力时，应做第4章独立配置或插件，只提供单 agent 需要的能力，不复制第3章整套 bundle。第4章中同一个 agent 执行任务、提出自身改进，通过确定性验证后才接受新版本。具体开发边界见[RSI 计划](../experiments/self_evolution/PLAN.md)。当前没有自动 RSI 运行器或已验证的收益结果，网页里的插件设置不能替代它。

第4章本机 profile 配置入口为：

~~~powershell
notepad ../dsh-home/chapter4/profiles/web-ssh/cordis.patch.yml
~~~

只在此 profile 安装未来第4章专用插件，并保留单 agent 补丁。安装新插件之前需要确定包名、固定版本与能力边界；当前无需重新安装已具备的 SSH 插件。

## 5. 改完怎么检查

下面仅生成配置，不调用模型、不运行仿真：

~~~powershell
./PrincipiaBlastFoam-DSH/deployment/windows/Start-Principia.ps1 -Chapter 3 -Ssh -DumpConfig
./PrincipiaBlastFoam-DSH/deployment/windows/Start-Principia.ps1 -Chapter 4 -Ssh -DumpConfig
~~~

第3章应出现 principia-retrieval-mcp 和上表五个专家 id；第4章应没有这些条目。第4章的 tool-subagent、tool-subagent-fork、tool-subagent-control、tool-subagent-list-agents、tool-workflow、workflow-worker-thread 应各自标为 disabled: true。两章均应有 remote-ssh-manager。

生成配置只能证明装配内容。再次启动后，选择对应远端工作区，用新手手册的只读检查任务验证用户、路径与求解器环境；专家是否实际使用工具、MCP 能否访问算例还需查看真实工具记录。

本指南依据当前已安装 profile、项目配置和固定版本的本地 DSH/SSH 插件源码编写；未宣称已验证所有网页点击或正式仿真实验。
