# 第4章单agent RSI：研究任务与自主探索计划

更新：2026-11-17。状态：研究待开展，尚无本设计下的实现验收或RSI收益结果。本计划规定目标、研究边界和所需证据，不规定按序完成的工程步骤。

## 给执行agent的任务

在OpenFOAM/blastFoam爆炸仿真领域，探索如何让同一个基础DSH agent通过持久自修改，提高任务能力及继续改进自身的能力。任务执行、自改进逻辑、外部验收和持久经验均可演化，基础权限、底层模型与预算保持固定。利用已有真实算例推进研究，同时逐步建设独立评测集；不必等待完整评测集建成才开始探索。

研究定义以[第4章共享设计](../../../graduation-thesis-materials/graduation-research/chapters/chapter04.md)为准。执行前结合本项目AGENTS.md、本地文献页码笔记、实际代码和数据现状判断可行路线。成功标准是形成有证据支持的方法和结论，包括无收益、退化及适用条件，而不是逐项实现预设架构。

## 自主决定的内容

agent可以自行选择研究假设、技术路线、算法、内部表示、接口、候选生成与搜索方式、经验组织、诊断方法、验收改进方案及工作顺序；也可以根据开发证据替换或放弃无效方案。共享设计中的T/I/V/M是分析维度，不要求实现为四个独立模块。

算例、样本量、轮次、每轮候选数、具体阈值、对照组合与统计方法均应结合研究问题、证据和已授权预算确定。本计划不指定优先算例，不要求固定轮数，不要求实现所有候选对照。共享设计中的接受机制和对照表是可检验的起点，允许提出有同等辨识能力或更合理的替代方案。

探索期允许调整方法，但应记录关键取舍及依据。正式评价前固定研究主张、方法版本、数据划分、指标、接受与回退规则、资源上限和分析方法；评价后改变这些内容须作为新的评价版本，不能根据测试成绩事后更换成功标准。范围内的方法探索无需逐步请求确认；改变用户研究边界或增加未授权资源时才需另行确认。

## 必须回答的研究问题与证据

以下内容可以交叉推进，按依赖和信息价值安排，不是阶段顺序。

| 研究问题 | 需要形成的证据 | 自主探索空间 |
|---|---|---|
| 哪些真实任务能支持当前研究？ | 来源与资格可核对，开发暴露可追溯；区分结果分析、诊断和完整求解的成功含义 | 选择案例和任务粒度，发现数据缺口，边研究边补充数据 |
| 递归承接自身修改为何可能有效？ | 初始能力、持久版本变化及后续实际使用证据；区分agent修改和研究者修复基础设施 | 修改表示、搜索策略、经验利用和递归机制 |
| 外部验收如何改进而不制造虚假收益？ | 独立参考下的假成功、误拒绝、物理有效性和成本证据，说明未覆盖风险 | 验收实现、资格检查、接受准则及验证资源分配 |
| 如何接受修改并控制退化？ | 可追溯的接受、拒绝、证据不足及回退结果；恢复后状态一致，失败和成本不消失 | 比较方法、阈值、保持性检测及恢复实现 |
| 是否只是任务能力提高，还是更会自改进？ | 同一起点、相同信息与预算条件下产生后继版本的能力比较，后继评价与候选选择分离 | 可采用策略移植或其他受控设计；无法分离时限制因果结论 |
| 收益来自递归、额外搜索、经验积累还是验收变化？ | 与具体研究主张对应的公平对照，报告失败、拒绝、回退和实际资源消耗 | 自主选择最有辨识力的对照与消融，不机械凑齐组别 |
| 结果能推广到什么范围？ | 独立来源族上的评价或明确的小样本限制；可复算的结果与不确定性 | 随数据成熟安排评价，不预设显著收益或泛化成立 |

可以先用现有产物、离线分析或小规模真实调用检验最关键的不确定性；选择由证据条件决定。夹具、人工故障注入及短时求解应保留真实身份，不能替代完整任务结果。若一条路线受阻，继续其他能够推进研究的问题，并说明阻塞对结论的影响。

## 不因自主探索而改变的边界

- 研究对象为独立单agent RSI；DSH只是框架。不继承第3章角色编排、预设轨迹或多角色bundle，不创建额外协调、反思或评审agent。确定性验证与统计程序不算agent。
- 允许任务执行、自改进逻辑、外部验收及经验演化；固定基础权限、模型身份和权重、任务执行及累计改进预算。预算与权限不能由候选自行重置。预算上限内可探索资源分配策略，正式对照须保持可比。
- 候选验收器不能批准自身。研究侧独立审计保留固定物理要求和共同最终口径；修改验收不能靠降低成功标准获得收益。接受与回退机制应可核查，但不限定唯一算法或状态名称。
- 开发反馈、接受候选所用的开发探针与最终封存评价分开。最终测试不参与本轮选优、接受或回退；查看后用于调整方案须登记暴露并另开评价。来源族与同源变体不得通过改名变成未见测试。
- 保留原始证据、历史框架身份、失败记录、完整分母和累计成本；未知、失败和未运行分别记录。新增任务或纠正参考依据须有版本，不悄悄改变已有比较。
- 现有授权内自主推进；缺少明确运行额度时先做离线研究并给出具体资源需求。远端计算遵守[集群入口](../../../supercomputer-simulation/README.md)、[安全说明](../../../supercomputer-simulation/SECURITY.md)、[维护约束](../../../supercomputer-simulation/AGENTS.md)及[批处理规程](../../../supercomputer-simulation/BATCH_JOBS.md)。旧作业批复不等于新预算。
- 默认不改论文、PPT，不做Git操作，不启动第2章退役工作器。本计划本身不授权新的实验运行。

交付应能回答：尝试了什么、为何选择或放弃、实际发生了什么、支持什么结论、还缺什么证据。保留设计与代码、模型配置、数据及评分依据的版本或哈希，能追溯父子修改、数据可见范围、决策和成本，并提供必要的复算方法。文件名、目录内部结构和工具实现由agent按项目惯例决定，不为满足清单堆叠文档；凭据与私有地址不进入可提交材料。

完成程度按研究证据报告，不按预设步骤打勾。只有实际证据支持时才写“已实现”“有效”或“可推广”；尚不足以区分任务能力与自改进能力时应明确指出。将重要方法变更同步共享设计，保持本入口简洁，并说明论文与PPT是否仍待同步。
