# 第4章单agent RSI：可直接交给Codex的执行清单

更新：2026-11-16。状态：待执行。以本轮共享设计为准，任务执行、自改进逻辑和外部验收均可演化。尚无本设计下的控制器验收或RSI效果结果；以下勾选项均未因写好设计而视为完成。

## 给执行agent的任务

在爆炸仿真领域实现并验证独立DSH单agent递归自改进：任务执行T、自改进I、外部验收V与持久经验M允许演化；基础权限、模型与预算固定。边建设评测集，边利用已具备证据的真实算例推进开发试点，最后在冻结的独立任务上检验收益。逐项完成下列工作并留下可复核产物，不以计划或模拟运行冒充真实实验。

研究定义唯一来源为[第4章共享设计](../../../graduation-thesis-materials/graduation-research/chapters/chapter04.md)。本文件只维护实施步骤与交付。执行前读本项目AGENTS.md、共享设计、文献页码笔记及数据集入口；以用户后续明确指示为准。

默认不改论文、PPT，不做Git操作；不启动第2章退役工作器，不覆盖历史结果。不得加载第3章多角色bundle、spawn/subagent工具或其预设轨迹。确定性审计、验证、统计程序不算额外agent。研究中的每次执行只有一个agent；可以顺序运行对照与测量副本，不创建协调／反思／评审agent。

本轮交接允许先实现、整理材料和进行已有授权范围内的试点。远端计算前必须读 `supercomputer-simulation/README.md`、`SECURITY.md`、`AGENTS.md` 与批处理规程；旧案例作业批复不等于新的运行预算。缺少明确运行额度时，先完成离线工作并列出具体待授权作业及预算，不能自行无限运行。

## P0：核对现状并建立最小可执行规格

- [ ] 核对真实代码与兼容性状态，不将旧README的“尚未实现”当成当前唯一依据。列出现有可复用服务、缺失组件、配置与宿主版本。
- [ ] 核对人工入选9场景的实际文件及manifest；目前正式参考基准为0。优先审查S01钢筒、S10 RP80与S12 TNT自由场，最终按可运行性、证据和成本选2—3个开发场景，不因名称相近假定独立来源族。
- [ ] 对每案记录：原件路径／哈希、工况、求解器环境、几何／材料／边界、有效测点与单位、原始结果、已获批范围、可用数值参考、缺失项、预估复跑资源。扫描件或LFS占位不算已取得原件。
- [ ] 区分可做结果分析、可复跑、可比较物理误差、可作正式评价四种资格；不设“人工入选即全部通过”。已知真实算例不足时仍继续结果回放、验收器与运行器开发，列明端到端阻塞。
- [ ] 冻结开发批次的模型、T0/I0/V0/M0、工具权限、每题执行上限、候选生成／验证上限、累计token和CPU／墙钟预算、失败重试及停止条件。费用若不可观测标缺失，不填0。
- [ ] 输出run_spec与资源估算。资源上限使用用户已授权值；未获明确额度的付费模型和集群运行保留待执行状态。

验收：能从规格定位真实输入，知道哪些阶段可运行及何时停止；没有把开发材料标为封存测试。

## P1：评测集建设与试点双线推进

- [ ] 在第4章任务目录建立任务族与来源映射、暴露登记；只引用原始物理案例，不导入第3章agent执行轨迹作学习经验。
- [ ] 每个可用场景先形成任务卡：起始状态、物理要求、可改参数、必要输出、资源上限与评价资格。agent侧只提供完成任务所需信息；参考配置、标签和审核答案留在评分侧。
- [ ] 建立三种独立统计层：已有结果的提取分析；基于可运行配置的修改／诊断；要求实际求解与交付的端到端任务。前两种通过不能充当第三种成功。
- [ ] 建设验收样本：真实合格产物、真实失败产物及受控反例。反例包括缺测点、错单位、错工况归属、未达到终止时刻、非有限值、空产物、截断时程、过期结果、伪成功日志。变换以副本为对象，记录修改位置及已知标签，不改原始证据。
- [ ] 正例资格不足则标unknown，不作为合格参考。压力定义、测点位置、时间零点、参考误差及近零分母处理须逐案有依据；不直接继承第3章尚待冻结的30%／15%阈值。
- [ ] 每轮可用小批次保持不变；新增案例或证据新开批次并记录版本。开发已暴露的场景及其同族变体不进入未见测试。
- [ ] 同时建设未来未暴露的任务族池，由评分侧保管。构建者与实验agent的可见范围分离；若可用任务族不足，不承诺泛化结论。

验收：形成可用于试点的任务包、反例包和独立来源登记；评测集未完成不阻止工程试点，试点也不透支未来测试身份。

## P2：独立运行器与版本接口

- [ ] 建立独立单agent profile，导出合成配置检查无角色bundle和spawn入口；验证基础集群提交、状态查询和结果回收链路。
- [ ] 设计版本包T/I/V/M与稳定接口：任务执行、诊断／提案、候选应用、外部验收。I接收允许的经验与版本描述，不能读取隐藏参考和封存测试。
- [ ] 实现隔离的候选工作目录及原子版本切换；父版本只读。产物、任务ID、配置、代码与求解收据可追溯。
- [ ] 固定权限与预算执行器在候选可写范围之外；测试候选无法重置预算、扩权、更换模型、篡改参考或增加agent。
- [ ] 支持故障恢复、重复加载、进程中断后的恢复与完整回退。失败证据和累计成本不随版本回退消失。
- [ ] 按项目约束运行相关Python测试、bundle检查、profile配置检查、MCP冒烟与相关benchmark用例；未涉及的项目检查注明不适用依据，运行不了的保留真实错误。

验收：先用确定性夹具验证接受、拒绝、回退及恢复，再接真实模型。夹具成绩只证明软件链路，不作为RSI收益。

## P3：实现可演化外部验收与独立接受规则

V可修改检查代码、抽取方法、检查项、阈值、组合判定与接受建议；本节的固定审计依据负责判断这些修改是否可靠，不充当额外agent。

- [ ] 建立V0审计集及独立资格集，区分agent可见示例、可返回有限反馈的资格样本和最终封存评价。为重复适应验证集设置固定查询上限；详细隐藏标签不可回流。
- [ ] 对V修改做影子回放：同一原始产物同时经过旧V、新V及独立参考判断。记录假成功率、误拒绝率、unknown覆盖率、判定差异和验证成本，不只报告新V通过率增加。
- [ ] 新V必须通过事前固定的资格条件。明确关键假成功上限、非劣容忍度、最小改善、验证样本量／重复次数；这些数值先以试点估计并在下一次运行前冻结，不能由候选自行修改。
- [ ] 固定资格程序测试：全通过验收器、空结果验收器、放宽单位／工况检查、偷读参考及修改计时／统计的候选应被识别。对更准确但更严格、降低误报或降低成本的合法V也须有能通过的正例。
- [ ] 决策状态至少含 proposed、ineligible、qualified、accepted、rejected、inconclusive、rolled_back。unknown或证据不足进入inconclusive，不算成功。

接受路径必须在提案时声明：

| 路径 | 条件 | 禁止的捷径 |
|---|---|---|
| Q 任务质量提升 | 独立配对任务质量达到最小效应，旧能力保持非劣，V资格合格，成本不越界 | 用候选V的通过率替代外部任务质量 |
| R 验收改善 | 任务质量非劣，V对独立参考的一致性／假成功或误拒绝指标改善，其他关键错误不超限 | 只增加拒绝率或只放宽标准 |
| I 改进能力提升 | 任务质量非劣，在独立开发探针、同一起点和预算下的改进能力达标 | 用最终封存探针反馈选择候选 |
| C 成本降低 | 任务质量及验收可靠性非劣，事前指定成本指标改善 | 减少必要求解、漏计失败或提高预算 |

开发首批可仅启用Q、R，待同一起点评价可运行后再启用I；启用状态写入run_spec，不把未启用路径算作失败。所有路径的判定实现固定于研究侧，候选可以提建议，不能自行改变本轮规则。

- [ ] T/I/V/M联合候选先验证V资格，再由同一固定审计口径配对父子版本；候选V不能批准自身，合格新V在下一轮才生效。
- [ ] 接受后遇到预定义运行异常、审计不一致或保持性退化时，恢复最近审计合格版本；若无合格恢复点，停止而非强行继续。保存原因、被取消的任务及资源消耗。
- [ ] 正式测试只在预定检查点离线计算，结果不回到agent或开发者本轮决策；若研究者据测试调整方案，登记暴露并重开研究批次。

验收：有真实失败与正确产物的拒绝／接受例，且在已覆盖的反例上验证降低验收标准不能制造研究成功；报告未覆盖情形。

## P4：用现有真实算例启动开发试点

- [ ] 先冻结基础版本，测量实际任务能力和成本；失败先分类为任务／环境／配置问题。修复基础设施后另记批次，不能混作agent进化收益。
- [ ] 从结果分析任务开始验证V修改，再对具备运行条件的真实案例开展完整执行；至少记录一条真实任务轨迹和一轮真实候选验证。不能人为保证一定有候选获接受。
- [ ] 第一批建议最多3个递归轮次，每轮1个候选，作为流程试点上限；累计预算更早耗尽则停止。轮数是建议起点，须在run_spec冻结，不是正式实验样本量。
- [ ] 分别演练T变化、I变化、V变化及完整版本回退；可用人工构造故障测试回退机制，但必须标为工程注入，不能计为agent自然退化。
- [ ] 汇总被接受、拒绝、无结论的提案、实际行为变化与后续使用证据；只改文档或未被调用的代码不计为能力贡献。
- [ ] 输出试点报告，包括逐题结果、资源、验收差异、暴露情况、阻塞及下一批数据需求。不用小样本p值或重复次数伪装独立样本规模。

验收：即使观察到无收益，也交付可复核闭环和否证结果；不为形成正结论更换分母或挑选运行。

## P5：同一起点的自改进能力测量

本节指封存的能力测量，结果不用于本轮接受或回退。P3的I路径另用独立开发探针：样本、来源族和记录与封存测量分开，按相同测量方法执行，仅返回预先规定的反馈，查询与成本纳入累计预算。两类探针不得复用为未见测试。

- [ ] 从预定检查点提取I0、It，验证接口兼容；明确模块参数、提示、代码和相关依赖。不能合法拆分时注明整体测量，不能宣称I的独立因果贡献。
- [ ] 每次从同一T*、V*、M*与相同任务经验开始，仅替换I；预算、反馈范围、随机化安排和可修改空间相同。旧／新策略均可读取相同目标包，不给新策略额外历史记忆。
- [ ] 每个测量副本只有一个agent，顺序运行；每次重置状态，禁止副本之间经验串流。测量结果不回写进化链。
- [ ] 分开候选生成／选择任务与后继版本评价任务。以独立评价集上的父子差值测有效改进，不以接受率替代能力。
- [ ] 报告固定预算下的后继质量增量、有效候选比例、失败／无候选比例、全部成本和重复运行波动。无效或未运行分开；已运行失败不得从分母删除。
- [ ] 增补(I,V)联合移植，与只移植I比较协同作用；最终任务评分仍使用同一固定审计口径。
- [ ] 从各自真实检查点继续改进作为补充，明确其起点强度、剩余提升空间和经验暴露不同；不要仅凭后期增量更大认定“更会改进”。

验收：能给出任务能力与改进能力两个独立结果，或诚实说明证据尚不足以区分。

## P6：对照与预算分配

| 组 | 做法 | 核心比较 |
|---|---|---|
| A | 冻结T0/I0/V0/M0，只做任务内正常修复 | 初始能力 |
| B | 相同累计预算，固定I0、V0，每个候选从T0/M0产生，只部署一次 | 一次部署与递归差异 |
| C | 固定I0、V0，反复改当前T/M | 固定改进者基线 |
| D | T/I/M递归，V0固定 | D−C隔离改进逻辑演化 |
| E | T/I/V/M递归，V经独立资格核验 | E−D测验收演化增量 |
| F | 仅持久经验／技能内容M更新，控制逻辑固定 | 经验积累解释，次级 |
| G | 取消保持性接受条件，保留基础约束、预算与固定最终审计 | 退化机制消融，仅开发阶段 |

C与D的初始条件、数据、可改T/M和反馈一致，仅I是否可持续更新不同。固定I0可检查当前目标T/M，但自身策略不更新；不另设运行中的meta-agent。E与D只改变V可演化性。B与D比较时保持可改T/I/M范围一致；B的候选I可作为最终产物，但不参与后续候选生成。B必须记录每个候选的初始父版本、反馈与选优次数；不能把一次低预算提案冒充等预算对照。

- [ ] 先做A/C/D/E工程试点，B用于正式递归结论必须补齐；F/G为次级且按资源决定，未运行不得写成结论。
- [ ] 各组任务执行预算一致，改进预算上限一致；失败、拒绝、验收升级、探针及回退成本分别记账。不能用相同轮数代替等成本。
- [ ] 开发期估计重复运行波动、任务族数量需求与主要效应阈值。正式样本量和多重比较处理在评测集可用后冻结，不预先承诺显著收益。

## P7：正式评价准入与交接

- [ ] 正式任务族、参考依据、评分标准、权限和预算均冻结；完成暴露审计。没有足够独立任务时停留在试点，不把已用案例重新命名成测试集。
- [ ] 固定初始版本、最终及中间检查点选择规则；最终测试不选最佳迭代。报告实际接受版本曲线，历史最好曲线仅作补充。
- [ ] 任务族作为统计单位；重复运行估计随机性而不是增加场景数量。完整成功、误差、退化、假成功、误拒绝与成本分别报告；失败用完整分母，unknown与未运行单列。
- [ ] 形成跨版本、跨组的结果表和可复算脚本，给出无收益／退化等否证结论。V变化时对保存的原始产物用共同审计版本重评，旧判定保留。
- [ ] 更新本目录README当前阶段、已完成勾选项、campaign链接与下一步；不要复制运行日志或堆叠新计划文档。
- [ ] 交付最终执行摘要：完成事项、可复现命令、真实结果、未完成项与原因、资源使用、后续是否具备正式实验条件。

当前执行起点为P0；先完成离线清点、数据包、控制器与确定性验证，再按已授权预算开展真实调用和集群任务。实现／运行失败时保留证据并继续不受阻塞的任务，不将失败改写为成功。
