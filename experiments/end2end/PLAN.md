# 第3章正式批量实验前置工作

更新：2026-11-23。本计划替代过期的18题派发队列、旧预算和旧重试安排，不改变研究问题、评价标准或已有冻结成绩。当前不启动批量实验。

研究问题：相同模型、公开输入、基础权限和可比资源下，专业系统与原始DSH在完整工程交付、适用范围和成本上的差异。不同任务类型和开发暴露分别报告。

## 必须完成的准备

1. 冻结本批任务清单、公开包哈希、来源家族与暴露身份。已有18题、24题及后续诊断不自动合并成独立测试集；外部测试未核验，不查找或导入。
2. 准备同一Linux底座上的两臂可重复运行身份：上游、应用实际文件、依赖锁、工具/技能、模型参数。应用大量未提交迁移改动须审查并形成明确部署manifest，不能仅引用Git基点。
3. 提供按任务配置的调度与交付入口。当前single_case_bridge限定100单元、8份字典、icoFoam和0.02秒，不是通用批量调度器，也不代表blastFoam已验收。各任务所需求解器、节点资源、输入与输出契约分别验证。
4. 验证两臂公开输入边界、研究侧评分材料隔离和独立回执归属。独立目录、grant字段和danger-full-access均不是操作系统隔离；不能只因设置isolation_accepted就声称证据成立。
5. 新批次独立模型账本、节点上限、总限额、持久停止状态、未知提交先查询及失败策略。Web的100次额度仅用于人工调试。正式批次是否允许人工恢复以及如何计入结果，须事前定义，不能临时用交互验收恢复替代正式规则。
6. 从正常入口进行无模型、无节点提交的计划预览，核对完整任务分母、每臂资源、唯一运行目录、封存与独立复核入口。只有明确授权后才进入真实批次。
